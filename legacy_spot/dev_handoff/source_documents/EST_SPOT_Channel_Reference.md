# SPOT R1.5 — Estimating Workflow Reference: How to Build & Run Estimates

> **For:** The AI assistant running SPOT in EST mode
> **Scope:** Building JSON payloads for SPOT, delivering them to the estimator, and using `spot_engine.js` / `spot_runner.js` directly for quick-quote sanity checks.
> **Status:** Verified penny-exact against live SPOT app across 10 qty slots, 3 test cases. Validated on 773-job iQuote fleet (D-110 FINAL, 2026-04-24): segment Cost R² 0.9690, segment Sell R² 0.9496, fleet cost Δ +6.55%, fleet sell Δ +8.30% (target +8.2%), margin lift +$76,488. See `DEV_D110_Design_Decision.md`.

## The channel in one paragraph

The EST assistant's job is to turn an RFQ into a JSON payload that loads cleanly into the live SPOT app via `window.__SPOT_LOAD_JSON(payload)`. The JSON is the primary deliverable — it is presented back to the estimator via `present_files`, and the estimator uploads or inspects it. SPOT's Preview Quote PDF is the approved customer-facing format (Rule 1 in `EST_SPOT_Quoting_Rules.md`) and is generated by the estimator pressing the Export button inside the app on their own machine. The runner (`spot_runner.js`) is a Node-side mirror of the app's calc pipeline, used for quick sanity checks and fleet regression — it takes the same JSON shape described below (Simple quotes only — Multi-Part is app-only).

---

## When to use each path

| Path | When |
|------|------|
| **JSON file via `present_files` (default)** | Every estimate, unless the estimator says otherwise. Fastest, reliable, estimator stays in control. |
| **Chrome MCP load via `__SPOT_LOAD_JSON`** | When the estimator says "load it," "drive it," "enter it for me," or asks for in-app verification. Use the base64-inject pattern below. |
| **Runner `runEstimate(json)` (Node)** | Quick cost sanity check before delivering, qty sweeps, flute swaps, or when the app is down. Simple quotes only. |
| **Chrome + Preview Quote PDF** | Customer-facing PDF. The estimator triggers Export inside SPOT — it opens a pop-up window that Chrome MCP **cannot capture** (see "Chrome-to-PDF limit" below). |

**Default:** JSON file. Everything else is on explicit request from the estimator.

## Simple-quote JSON — full field list

All fields are strings unless noted. SPOT auto-fills missing fields per `applyState`'s reset block. The runner (`spot_runner.js`) mirrors this for headless runs.

### Identification
| Field | Example | Notes |
|-------|---------|-------|
| `custName` | `"Skybox Packaging, LLC"` | Bill-to customer (broker if applicable). |
| `custRef` | `"PO 47309 / Spec Z112089"` | Project / PO / custRef — free text. |
| `custIdent` | `"Z112089-1"` | Customer part #. ⚠️ Top-level `custIdent` must match `bomItems[0].custIdent` in Multi-Part — D-081 scoping bug otherwise clobbers the active item. |
| `itemDesc` | `"MTD Case #9360 - MRO15486 RevD"` | Item description. |
| `boxStyle` | `"D/C"`, `"RSC"`, `"D/C Joined"`, `"Display Header"`, `"Display Base"`, `"D/C Non-Joined"` | Free text; appears in the header area. |
| `estInitials` | `"SPC"` | **Locked — always `SPC`** for AI estimates (Rule 2). UI blocks manual entry. |

### Quote type
| Field | Values | Notes |
|-------|--------|-------|
| `quoteType` | `"Simple"` \| `"Multi-Part"` | Simple = single item; Multi-Part = BOM of items. |
| `pricingMode` | `"Individual"` \| `"Matched Set"` | Simple always `Individual`. Multi-Part typically `Matched Set`. |
| `activeItemIdx` | `0` | Which BOM item is active on load. Multi-Part only; integer. |
| `setMarginPct` | `"0.40"` | Set-level GM target (Matched Set). |

### Board
| Field | Example | Notes |
|-------|---------|-------|
| `flute` | `"B"`, `"C"`, `"E"`, `"BC"`, `"EB"` | See UI Map `#board-flute`. |
| `boardGrade` | `"200"`, `"ECT 32"`, `"ECT 44"`, `"ECT 48"`, etc. | SPOT's singlewall grades: `200`, `ECT 32`, `ECT 44`, `ECT 48`, `ECT 55`, `ECT 61`, `ECT 71`, `ECT 82`. Doublewall: `ECT 42` / `48` / `51` / `61` / `71` / `82`. **Grades not in this list (e.g. `40 ECT`) substitute DOWN to the nearest Mullen-equivalent stock sheet — rule 4. ECT 44 is uncommon at SPC; manual mill check (DEV-011, no popup).** |
| `outsideLiner` | `"Kraft"`, `"42# Kla-White"`, `"42# Kemi-Lite"`, `"42# Bleached White"`, `"33# Kla-White"`, `"56# Kla-White"` | Use `"None"` as a stand-in for default kraft when setting up from a reset state — applyState keeps `"None"` as "default kraft" semantically. |
| `insideLiner` | same options as outside + `"None"` | `"None"` = default kraft on the inside. Customer phrase "Plain MW inside" → `"42# Kla-White"` (registry ⚠️). |

| `fscEnabled` | `true` \| `false` | FSC/SFI. If on, $25/order amortized into board (D-086; migration from $15 fires on load). |

| `under5MsfFee` | `"0"` | **Rule 3 — always `"0"`.** WF shop does not carry the corrugator charge. |

## Multi-Part JSON — BOM structure

Multi-Part estimates have a `bomItems[]` array in addition to the top-level active-item fields. The top-level fields mirror the active item (per D-098 fallthrough in `applyState` at JSX L2423); the `bomItems[]` array carries the full per-item state for every component.

**bomItem shape:**
```json
{
  "id": "item-N17730",
  "desc": "N17730 - Counter Display Tray",
  "custIdent": "N17730",
  "type": "Manufactured",
  "pcsPerSet": 1,
  "state": {
    "itemDesc": "N17730 - Counter Display Tray",
    "boxStyle": "D/C Non-Joined",
    "flute": "E", "boardGrade": "ECT 32",
    "outsideLiner": "42# Kemi-Lite", "insideLiner": "None", "medium": "None",
    "fscEnabled": false, "fscFee": "25.00", "under5MsfFee": "0",
    "quoteMode": "One-Up", "oneUpW": "30.5", "oneUpL": "45.375",
    "qtys": ["250", "500", "", "", ""], "selSlot": 0,
    "printReq": "Yes", "printMode": "Satin", "printSides": "1-Sided",
    "whiteInk": "No", "saber": "No", "saberCuts": "1", "saberBlanksOut": "1",
    "cadPricingMethod": "By Difficulty",
    "cadDifficulty": "Complex", "crestComplexity": "Complex",
    "totalRuleInches": "0", "perfPct": "0",
    "productMats": "No",
    "handStripping": "Yes", "perimeterStripping": "No", "strippingComplexity": "Complex",
    "handGluing": "No", "jointsPerPiece": "1", "gluingComplexity": "Standard",
    "tape": "No", "tapeType": "Clear",
    "cuttingDieCost": "0", "dieTreatment": "None", "dieAmortMethod": "Markup",
    "prepressTreatment": "Auto"
  }
}
```

**Outer shell:**
```json
{
  "custName": "...",
  "quoteType": "Multi-Part",
  "pricingMode": "Matched Set",
  "activeItemIdx": 0,
  "setMarginPct": "0.40",

  // top-level fields mirror bomItems[0].state
  "flute": "E", "boardGrade": "ECT 32", ...
  "oneUpW": "30.5", "oneUpL": "45.375",
  "qtys": ["250", "500", "", "", ""],
  ...

  "quoteFOB": "Destination",
  "destZip": "54902",
  ...

  "bomItems": [ { ...item 1... }, { ...item 2... }, ... ]
}
```

**Top-level `qtys` must equal each item's `bomItems[i].state.qtys` in Matched Set mode** (BOM Builder sets them together at `commitBom` — JSX L1529–1533). Each item can have a different `pcsPerSet` multiplier that BOM Builder applies; when building a JSON by hand, set `pcsPerSet: 1` and put the already-multiplied qty directly in `state.qtys`.

**Item type values:** `"Manufactured"`, `"Purchased"`, `"Fulfillment"`. Default is Manufactured. Purchased items carry `purCostByQty` + `purLotCost` instead of board/dim fields.

## Chrome MCP load — base64-inject pattern

When the estimator says "load it," use this JS through `javascript_tool`. The JSON is base64-encoded to survive quoting inside the JS string. The existing app tab (found via `tabs_context_mcp`) is the target — SPOT's `applyState` is reset-first (D-080/D-087/D-098), so the current tab's estimate is replaced cleanly without residual state.

```javascript
(() => {
  const b64 = "<base64 of the payload JSON>";
  const payload = JSON.parse(atob(b64));
  const ok = window.__SPOT_LOAD_JSON(payload);
  return { loaded: ok, custName: payload.custName, itemCount: (payload.bomItems||[]).length };
})()
```

**Return contract:** `window.__SPOT_LOAD_JSON` returns `true` on success, `false` on a validation or apply error (check the console via `read_console_messages` for the actual error). The tab title updates to `SPOT R1.5.3 — <estNum> — <custName>` after the next React cycle.

**Preserving prior tabs:** loading replaces the *active* tab's state only. Prior estimates are auto-saved in `wftabest{timestamp}` archives (Load Estimate modal) — the estimator can reload them if needed. To keep a previous estimate visible in a separate SPOT tab, the estimator should click "+ New Tab" in SPOT's tab bar *before* the load.

## Chrome-to-PDF limit (recognized 2026-04-22)

SPOT's Preview Quote → Export button calls `window.open("", "_blank")` and writes the printable quote HTML into a new browser window. That new window is NOT in the Chrome MCP tab group — it's a native browser pop-up that the extension doesn't see. There is no MCP path to capture the PDF that the estimator's Ctrl+P would produce.

**Channel rule:** when the estimator asks for "the PDF in here," flag this up-front. Options:
1. Load the JSON, return with "Export → Ctrl+P on your side" instructions. (Fastest; estimator keeps the native workflow.)
2. Screenshot the Preview Quote modal (NOT the Export pop-up). This is a visual reference, not a true PDF.
3. Skip the Chrome round-trip entirely; deliver only the JSON.

Do not start the Chrome load with intent to "figure out PDF capture along the way." Surface the constraint at the top of the turn.

## Never-set fields (Rule 1 + calibration protection)

- `routeOverride` — always omit. Auto-route only.
- `incaRate`, `cadRate`, `crestRate`, `saberRate`, `handStripRate`, `handGlueRate`, `kemiTariff`, `palletPrepFee`, `spoilagePct`, `regMR`, `whiteMR` — omit. Rate migration in `applyState` L2447–2466 will snap them back to `RATE_DEFAULTS` anyway and fire the amber "costs updated" toast.
- Manual `gmByTier` or `sellByTier` overrides — only set if carrying forward a prior quote's locked sell prices; otherwise let the GM curve apply.

## Runner quick-start (Simple quotes only)

```javascript
const { runEstimate } = require('./spot_runner.js');
const json = require('./my_estimate.json');
for (let slot = 0; slot < json.qtys.length; slot++) {
  if (!json.qtys[slot]) continue;
  const r = runEstimate(json, slot);
  console.log(`Qty ${json.qtys[slot]}: sell $${r.sellPerPc}/pc, GM ${r.gmPct}%`);
}
```

**Runner scope:** Simple quotes only. Multi-Part is an app-only feature (`commitBom` + per-item calc pipeline is in the JSX React code, not mirrored in `spot_runner.js`). For Multi-Part regression, use the live app via Chrome + `__SPOT_LOAD_JSON`.

## Per-estimate intake folders

Every estimate gets a folder under `/home/claude/estimates/<folder_name>/` with:
- `intake_<folder_name>.md` — durable 14-section record per `EST_SPOT_Intake_Template.md`.
- `<folder_name>.json` — the payload shipped to the estimator via `present_files`.

Folder naming convention: `<customer_short>_<po_or_project>_<part_ref?>` — e.g. `skybox_47309_mro15486`, `lm_schieks_126292`, `pca_gol_j57667`.

Each session's folders are kept as references for the next similar-shape estimate (Simple / 2-item Multi-Part / 4-item Multi-Part with non-native print).
